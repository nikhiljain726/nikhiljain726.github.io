Your CRM needs infrastructure now

AI & agent workflows  ·  Jul 2026  ·  4 min read

An AI agent is only as good as what it can touch. Give it a chat window and it writes you an email. Give it your CRM and it can run your pipeline. The difference is infrastructure.

For a while the gap was that the tools could not act. They could suggest, but a human still had to click. That is changing fast, and the bottleneck is no longer the model. It is whether the model has a safe, complete way into your systems.

For a CRM, that way is an MCP server. It exposes the CRM to any AI client as a set of tools it can call: read a deal, score a contact, merge duplicates, write one field across a hundred records.

In the age of AI, the CRM is not the product. Access to it is.

The connectors that ship by default tend to be read-only and thin. They let an agent look, not act. The real work lives in the writes and the cleanup, and those need guardrails: a dry run before anything destructive, and a log of every change so you can see and undo what happened.

So I built my own for Pipedrive, with 36 tools and those guardrails baked in. Not because building it was fun, though it was, but because without it the agent is a very smart intern who is not allowed to use the keyboard. I wrote up how it works in the CRM cleanup, and the code is open on GitHub.
