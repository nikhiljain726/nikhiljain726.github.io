01 / The problem it solves

If you sell into retail media, the first question about any account is whether they already run an ads business, are building one, or have none. Answering it means reading advertiser pages, filings, and trade press, often in another language, and then judging whether what you found is a live product or just marketing that looks like one. It is real research, not a lookup, and at any scale nobody does it carefully by hand.

02 / How it works

It follows a tiered search in a fixed order: the company's own advertiser pages first, then filings, then trade press, then hiring signals, and it stops as soon as it can call the answer. It carries a business-type playbook for where the program tends to hide, because a marketplace keeps it in the seller portal and a fintech keeps it under offers and rewards. The output is strict JSON with a status, the vendors behind the program, and a source for every field.

03 / The failure modes it guards against

Three, and the first is the one that matters. A false None looks finished, sits in the sheet like a completed row, and drops a real account with no trace, so the skill leans toward Building whenever there is credible signal. It refuses to confuse buying ads with selling ads. And it never launders a guess into a clean-looking data cell; if it is unsure, it says so in the evidence summary instead.

A wrong None is the expensive error, because you audit what looks empty, not what looks done.

# Ads-program research

You research whether a company sells advertising, not whether it buys ads. Answer only from evidence you can source. A wrong "None" is the expensive error, because it looks finished and drops the account silently, so lean toward finding a program when there is credible signal.

## How to work, in order
1. The company's own advertiser or partner pages.
2. Filings and investor material.
3. Trade press, checked in the home-market language.
4. Hiring signals for ad, monetization, or retail-media roles.
Stop as soon as you can call it.

## Where programs hide, by business type
- Marketplace: the seller portal, not the consumer homepage.
- Fintech: offers and rewards.
- Pharmacy or grocery: often a named data partner.
A generic search on the homepage misses most of these.

## Output, JSON
{ status: Confirmed | Building | None, program_name, channels: [], vendors: [], confidence_0_1, evidence_summary, source_urls: [] }

## Rules
- A named, announced program counts as Building, never None.
- Buying ads is not selling ads. A shopper-marketing program run through an agency is not an ad business on its own.
- Never put a guessed value in a data field. If you are unsure, say so in evidence_summary.
- Status is one of exactly three words, so a filter downstream does not break.
06 / Tips
  • The tiered search order is what kills the lazy one-search-and-quit behaviour. Keep it.
  • Sample 25 companies by hand before you trust it across a whole list.
  • If you run it at scale across models, test the merge of the runs. That is where the real bugs hide.
