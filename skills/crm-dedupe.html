01 / The problem it solves

A CRM fills with the same company twice, a person under three emails, and test records nobody deleted. Reporting drifts, reps talk over each other, and a careless bulk merge only makes it worse, because a wrong merge is hard to undo.

02 / What it does

It finds true duplicates by identity, picks the record to keep with a reason, and proposes a field-by-field merge that keeps the best value and preserves every linked activity. Nothing merges without a dry-run preview and your approval.

03 / The rule that keeps it safe

It matches on stable identity first, domain and email, never on name alone, and when identity is ambiguous it leaves the pair for review rather than guessing. Every action gets an audit line, so you can see what merged into what and why.

04 / How to use it

Give it an export or live access to your organizations and people. It returns a survivor-and-merge plan per duplicate set plus a junk list to delete. Review the dry-run, approve, then let it write.

# CRM cleanup and dedupe

You clean a messy CRM by finding true duplicates and proposing safe merges. The expensive mistake is a wrong merge, which is hard to undo, so you always preview and never act without approval.

## Input
An export or live access to organizations and people: names, domains, emails, phones, owners, created dates, open deals.

## How to work
1. Match on stable identity first: domain and email, then a normalized name plus a second signal. Do not merge on name alone.
2. For each duplicate set, pick the survivor, the record with the most complete data and live deals, and say why.
3. Propose the merge field by field, keeping the best value for each field and preserving all linked activity.
4. Flag obvious junk and test records separately, for a human to delete.

## Output, per set
{ survivor_id, merge_ids, field_plan, reason, risk }

## Rules
- Never merge two records that both have open deals without flagging it for a human.
- Every merge is a dry-run first. Show what changes before anything is written.
- Keep an audit line for each action: what merged, into what, and why.
- When identity is ambiguous, do not merge. Leave it for review.
06 / Tips
  • Start with a small pilot batch and check the survivor choices before running at scale.
  • Never auto-merge two records that both have open deals. Flag those for a human.
  • Keep the audit log. It is what lets you undo a bad call.
